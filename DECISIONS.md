# Decisions

| # | Phase | Decision | Why |
|---|---|---|---|
| D1 | 0 | Local Python is 3.12; code targets `>=3.11` and Docker image uses 3.11. | Brief fixes 3.11; no 3.12-only syntax is used except `StrEnum`/`datetime.UTC` (both 3.11+). |
| D2 | 0 | Tests run on SQLite; DB models use generic `JSON` columns. Migration `CREATE EXTENSION vector` runs on PostgreSQL only. | Hermetic tests with no Docker. A test asserts the migration matches the models. |
| D3 | 0 | The pgvector embedding column is NOT in migration 0001; it is added in Phase 5 with the `VectorStore`. `historical_incidents` stores `embedding_model`/`embedding_dim` metadata now. | Embedding dimension depends on the chosen model (one model per index). |
| D4 | 0 | ORM attribute for event metadata is `meta` (SQLAlchemy reserves `metadata`); `extra` used on other tables. API/contract field stays `metadata`. | Reserved name. |
| D5 | 0 | `Diagnosis` schema validates: conclusions need supporting evidence; `insufficient_evidence` forces `requires_human_review`; root + alternative confidences sum <= 1; alternatives ranked descending. The low-confidence review rule is the helper `needs_review(diagnosis, threshold)` because the threshold is config. | Brief says "true when confidence < configured threshold". |
| D6 | 0 | `event_id` = `ev_` + first 16 hex of sha256 over (UTC timestamp, source, service, resource_id, event_type, metric, raw_ref). Naive timestamps are treated as UTC. | Deterministic and timezone-independent. |
| D7 | 0 | Default evidence weights: temporal .25, resource .20, anomaly .25, semantic .15, dependency .15. | Placeholder; tuned on dev split only (Phase 4/7). |
| D8 | 0 | Config priority: init > env (`CLOUDDIAG_*`, `__` nesting) > `.env` > `config/default.yaml` > defaults. API keys are env-only and held as `SecretStr`. | Brief: YAML + env. |
| D9 | 0 | DB connections to non-SQLite URLs use `connect_timeout=3`. | `/health` must fail fast when the DB is down. |
| D10 | 0 | Frontend placeholder is a static page served by nginx in Compose. | Real React app is Phase 9. |
| D11 | 0 | Contracts for `Anomaly`/`MetricSeries`, `ScoreWeights`/`EvidenceItem`, `CollectionRequest` were added beyond the brief's list because the interfaces need typed signatures. | Interfaces cannot be typed otherwise. |
| D12 | 0 | The build brief is stored in the repo as `BRIEF.md`, with a status/amendments section appended at the end. | Keeps the spec next to the code it governs. |
| D13 | 0 | Remote is `https://github.com/navya906/incident-diagnosis-aws.git`, default branch `main`. `.venv`, `.env`, caches and generated data are git-ignored. | Requested by the user. |
| D14 | 0 | Single dependency source is `backend/pyproject.toml` (`pip install -e ".[dev]"`); no separate requirements.txt. `moto`/`boto3` moved to an `aws` extra, installed from Phase 2. | Avoids drift; keeps the dev install light. |
| D15 | 0 | Venv lives at `backend/.venv`; `scripts/setup.ps1` / `setup.sh` create it and run the tests. | One predictable location for all contributors. |
| D16 | 0 | Collaboration scaffolding added: README hand-off rules, CONTRIBUTING.md, PR template, GitHub Actions CI (ruff + pytest on Python 3.11), `.gitattributes`/`.editorconfig` (LF). | Lets several people continue work without context loss. |
| D17 | 0/1 | The Phase 0 gate item "`docker compose up` brings up api + db" is WAIVED (owner decision, 2026-10-06) so Phase 1 can proceed; it stays open in PROGRESS.md until someone with Docker verifies it. | Phase 1 is pure Python and file-based; Docker is unavailable on the dev machine. |
| D18 | 1 | Dataset = 100 standard (10 faults x 10 variants) + 12 red-herring + 6 insufficient-evidence + 6 compound = 124 cases. Red-herring/IE/compound cases are in addition to the 100. | Brief's minimums are met with headroom; categories stay cleanly separable for analysis. |
| D19 | 1 | Each incident is stored as two files: observable (`<id>.json`) and truth (`<id>.truth.json`). Incident ids are opaque hashes. | Structural guard against ground-truth leakage into prompts/collectors. |
| D20 | 1 | Descriptions are generated only from the alarm (metric + resource) plus a generic symptom sentence per alarm type. | Blinding by construction; checked by a forbidden-word test. |
| D21 | 1 | Insufficient-evidence cases inject a real fault, then strip telemetry (`alarm_only` keeps only the alarmed resource's metrics; `sparse` keeps that plus one other resource at 30% density). Ground truth is `insufficient_evidence` with primary resource = alarmed resource and no evidence ids; the underlying fault is kept in truth metadata only. | Makes "insufficient" true by construction rather than by opinion. |
| D22 | 1 | Determinism uses stdlib `random.Random("{seed}:{key}")` (stable across Python versions), no wall clock, values rounded to 4 dp, canonical JSON (sorted keys). Byte-identity is tested on one machine; libm `sin/cos` could in rare cases differ across OSes. Reference content hash for seed 42 is in `docs/offline-dataset.md`. | NumPy Generator streams are not guaranteed stable across versions; stdlib Random is. |
| D23 | 1 | Ground-truth evidence = visible trigger CloudTrail/Config events + first two key log lines + first two datapoints of each key metric whose injected effect has reached >= 50% of its peak. | Deterministic, checkable definition for evidence precision/recall in Phase 4. |
| D24 | 1 | Compound cases: primary label = the earlier fault; the second fault starts 3 to 7 min later and is listed in `secondary_labels`. | Brief does not define compound scoring; this keeps a single primary label for the main metric. |
| D25 | 1 | Count metrics (Sum) scale with the period (60 s vs 300 s); averages do not. Alarm time is the first datapoint after a 2 to 7 min detection lag that crosses 25% of the injected delta. | Matches CloudWatch semantics; exercises variable-resolution handling in Phase 3. |
| D26 | 1 | The fault-injection tool lives in `backend/app/offline/fault_injection.py` (importable, unit-tested in dry-run) and the CloudFormation template in `infra/test-stack/`. Dry run is the default; `--execute` is required to touch AWS. Revert state is stored in `.fault-state/`. | Testable without AWS; hard to run by accident. |
| D27 | 1 | The test stack's SQS/Lambda consumer covers `function_timeout` and `queue_backlog`; the default app image is nginx, so DB-dependent symptoms need a user-supplied image (documented). | Keeps the template small while every fault has a real injection path. |
| D28 | 1 | `ruff format` is the project formatter (CI checks it). The whole backend was reformatted once. | Avoids style churn between contributors. |
