| D41 | 3 | Detectors score each point against a trailing window measured in minutes (default 30), never using later points. Windows adapt to 60 s / 300 s data; missing points shrink the window; points with fewer than `min_history_points` (5) baseline values are not scored. | Handles variable resolution and sparse data without special cases; detection delay is realistic (no look-ahead). |
| D42 | 3 | Already-flagged points are excluded from later baselines by default (`exclude_anomalies_from_baseline: true`). | Otherwise a persistent fault is absorbed into the baseline within minutes; configurable. |
| D43 | 3 | Spread floor = max(0.01 x abs(median), 1e-6) for std and MAD. An initial 5% floor hid real 10% steps on low-variance series and was lowered to 1% after a unit test exposed it. | Flat series (e.g. a constant task count) must not divide by zero, but the floor must not mask genuine shifts. |
| D44 | 3 | Method definitions: moving average = abs(x - mean) / max(abs(mean), 2 std); rolling std = std of the last 3 points / baseline std; Isolation Forest fit per series on its first 30 min (features: standardized value and first difference), anomalous when -decision_function > threshold, `random_state` 0. | Simplest defensible version of each method named in the brief; IF assumes the window's start is normal, as all baselines do. |
| D45 | 3 | Evaluation: point precision (flags inside an injected window of the same series), window recall (injected windows with data that get at least one flag), delay to the first flag, series false-alarm rate. Windows without data (stripped telemetry) are not evaluable. The test split needs `--final`. | Range-based recall does not penalise ramp points twice; precision still counts every pre-onset or off-target flag. |
| D46 | 3 | Defaults stay at textbook thresholds (z 3.0, MAD 3.5, MA 0.5, rolling std 3.0, IF 0.0). | D49 | 4 | Graph: structural edges point dependent -> dependency (interface contract). Failure impact uses a derived impact graph with every edge reversed; `polls` edges also keep their forward direction (a failing consumer backs up its queue), `sends_to` does not. Node/edge types are closed sets (unknown types raise); a node seen only in an edge gets its type from the canonical id prefix. One builder takes `ResourceRecord`/`RelationshipRecord`, which real inventory discovery and the dataset both emit. | Upstream/downstream keep their meaning while blast radius and cause search follow how failures propagate, including the SQS consumer case. |
| D50 | 4 | Investigation window = [alarm - W, alarm + 10 min], W in {5, 15, 30, 60}. Anomaly detection runs on all collected events (it needs a trailing baseline); only events inside the window are ranked or chained. Alarm events are the trigger, not evidence candidates. Dependency component: 1 when the event's resource is affected or can reach an affected resource in the impact graph, 0.3 when only the reverse holds (symptom side), 0 when unconnected or with no graph. The first version decayed with hop distance; dev showed that this favoured the alarmed symptom resource (the ALB) over the cause side, so the decay was removed. | Causes precede alarms; a short tail keeps trailing effects and logs. Dev ground-truth evidence lies 15 min before to 10 min after the alarm. |
| D51 | 4 | Redundancy control: at most `max_per_group` (2) items per group (metric series, log template with numbers/hex ids masked, CloudTrail API call per resource, Config stream). Groups are ordered by their best score; within a group, members scoring >= 0.9 x the best are eligible and the earliest are taken. Ranks follow that order; each item keeps its own score. | Otherwise one anomalous series fills the top-K; first occurrences carry the information and match how ground truth is defined (D23). |
| D52 | 4 | Chains and candidate causes. Signals: mutating CloudTrail/Config changes, failed API calls, new WARNING+ log templates (first occurrence; templates seen before the window are background), anomaly runs of >= 2 points, alarms. Link a -> b when b is within 10 min after a and b's resource is a's or reachable from it in the impact graph within 3 hops. The anchor is the alarm (else the first anomaly run on an affected resource). Every signal with a link path to the anchor precedes it; it is a candidate cause when its resource also has a dependency path to the affected resource. Candidates are ranked by kind strength x temporal proximity to the onset (tau 10 min before, 3 min after); each carries its strongest chain (max summed strength) and the dependency path. Chains and candidate causes are reported alongside the ranked evidence and do not change the Section 2 score; A4 = `use_chains=False` plus temporal weight 0. Output is labelled "candidate cause", never causal. | Keeps the evidence score exactly the five-component formula and makes each ablation remove one thing. |
| D53 | 4 | Semantic component, local implementation: TF-IDF cosine between the event text and the blinded description, raised to 0.5 when the text contains a generic failure term (error, timeout, denied, refused, ...; no taxonomy words). Any object with `scores(query, texts)` can replace it; Phase 5 embedders will. | Works offline with no model download; the interface lets Phase 5 swap it without touching the ranker. |
| D54 | 4 | Onset estimate = earliest start of an anomaly run that is still active at the alarm (last flag at most 2 periods before it), on the alarmed series or on any resource in `impact_sources(affected)` (runs >= 2 points), starting at most 15 min before the alarm; else the alarm time (A3 lands here). Using only the alarmed series was a median 5 min late on dev; this version has mean absolute error 3.3 min (alarm time: 6.4 min), mostly 5-minute quantisation on 300 s data. | The temporal component and candidate-cause ranking need an onset, and the alarm lags the onset by 2 to 7 min (D25). |
| D55 | 4 | Evidence settings chosen on dev only. Detector for the anomaly component: z-score with threshold 6.0 (recall@10 0.55 vs 0.49 at 3.0; rolling std 3.0 was equal; MAD, moving average and Isolation Forest were lower). This closes D46 for evidence ranking; the `anomaly` section defaults stay textbook. Weights from the grid {0, 0.15, 0.3}^5 at W = 30, K = 10; rule: among configurations within 0.01 recall@10 of the best (0.605), take the one with the most non-zero weights -> temporal 0.15, resource 0, anomaly 0.3, semantic 0.3, dependency 0.3 (recall 0.601). Weights need not sum to 1. `resource` gets 0 because alarms sit on the symptom resource while evidence sits on the cause side. `ScoreWeights()` keeps the Phase 0 placeholders (D7); config and YAML carry the tuned values. All dev numbers are therefore in-sample. | Brief: weights and thresholds are tuned on dev only. The rule avoids collapsing to a 3-signal score whose advantage is within noise. |
| D56 | 4 | Contract additions (no existing field changed): `app/contracts/correlation.py` (`Signal`, `InvestigationWindow`, `EventChain`, `CandidateCause`, `CorrelationResult`), `EvidenceRanking`, and `make_evidence_id(incident_id, event_id)` = `evd_` + first 16 hex of sha256("incident|event"). Signal and chain ids are content hashes too. | Evidence ids must stay valid across re-rankings, K, windows and ablations so later citations can be verified. |
| D57 | 4 | Evidence evaluation: precision@K = ground-truth items in the top-K / items returned; recall@K = / ground-truth items; macro-averaged over incidents with ground-truth evidence (insufficient-evidence cases excluded); red-herring rate over red-herring cases; candidate-cause hit@n compares the cause's resource with the primary resource. Results go to `docs/experiments/phase4-evidence-ranking-dev.*`; `--tune` is dev-only and the test split needs `--final`. | Same conventions as Phase 3 (D45, D47). |
